---
title: Errors
description: One error shape and the status codes you can expect.
---

Every error response uses the same JSON shape:

```json
{ "statusCode": 404, "error": "Not Found", "message": "Photo not found" }
```

For validation failures `message` may be an array of strings, one per problem:

```json
{ "statusCode": 400, "error": "Bad Request", "message": ["limit must be an integer number"] }
```

## Status codes

| Code | Meaning | Typical causes |
|---|---|---|
| `400` | Bad Request | Invalid body or query, a malformed or tampered `cursor`, an upload containing a file that isn't a real JPEG, PNG or WebP image, or more than 20 files. |
| `401` | Unauthorized | Missing, invalid or expired token on a protected route, or wrong username or password on login. |
| `403` | Forbidden | A non-admin calling `/admin/*`. |
| `404` | Not Found | Unknown photo id, or a soft-deleted photo requested by a non-admin. Soft-deleted image files also return `404`. |
| `413` | Payload Too Large | An uploaded file over 15 MB, or a request body over the size limit. |
| `429` | Too Many Requests | Rate limit hit: 5 login attempts per minute, or 120 requests per minute per IP on other endpoints. Wait and retry. |

<Tip>
  On `401` from any endpoint other than login, discard the stored token and ask the user to log in again. Tokens last
  one hour and there is no refresh flow.
</Tip>
