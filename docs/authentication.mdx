## Getting a token

`POST /auth/login` with a JSON body `{ "username": "...", "password": "...", "remember": true }` returns:

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "tokenType": "Bearer",
  "expiresIn": 3600,
  "user": { "id": 1, "username": "demo", "role": "user", "permissions": [] }
}
```

- Tokens are JWTs signed with HS256. The payload is `{ sub, username, role, ver }`.
- Usernames are case-insensitive (stored lowercase).
- Every authenticated request re-reads the account, so role and permission changes apply immediately. Disabling an
  account or resetting its password bumps `ver` and ends all its existing sessions (`401`).
- Access tokens last **1 hour** (`expiresIn` is in seconds). Get a new one with `POST /auth/refresh` (below) instead of
  logging in again.
- Wrong credentials return `401` with a generic message, whether or not the username exists.
- Login is rate limited to **5 attempts per minute per IP**. Further attempts return `429`.

## Staying signed in (refresh tokens)

Login also sets an **HttpOnly** cookie, `pw_refresh` (path `/api/v1/auth`, `SameSite=Lax`, `Secure` in production).
Scripts can't read it; the browser sends it to the auth endpoints only.

| Endpoint | Does |
|---|---|
| `POST /auth/refresh` | Uses the cookie to return a new `{ accessToken, tokenType, expiresIn, user }` and **rotates** the cookie. `401` when there is no valid session (the cookie is then cleared). Limited to 30 per minute per IP |
| `POST /auth/logout` | Ends the cookie's session and clears it (`204`). Access tokens already issued stay valid until they expire |

- `remember: true` (the default, the web app's **Keep me signed in** box): the session lasts **60 days since it was
  last used** (`REFRESH_REMEMBER_DAYS`) and survives closing the browser. Each refresh extends it.
- `remember: false`: a browser-session cookie, and the session ends after **12 hours** unused (`REFRESH_SESSION_HOURS`).
- Every refresh issues a new refresh token. Presenting one that was already used more than 60 seconds earlier is treated
  as theft and ends that whole session. (Within 60 seconds it is accepted, so two tabs refreshing at once both work.)
- Resetting the password or disabling the account ends all refresh sessions too.
- The server stores only a SHA-256 hash of each refresh token.

The web app refreshes automatically about a minute before the access token expires, when a tab comes back into view,
and once more after any `401`; tabs share the result.

## Sending the token

Send it in the `Authorization` header on every request:

```bash
curl https://prewedding.leavchandara.com/api/v1/auth/me \
  -H "Authorization: Bearer $TOKEN"
```

Public photo endpoints (`GET /photos`, `GET /photos/{id}`) accept requests **with or without** a token. With a valid
token they add the per-user `isFavorite` and `isSaved` flags to each photo.

## Roles and permissions

There are two roles. **Admins** have every permission. A **user** can always browse, favorite, save, share and
download, and an admin can grant them any of these extra permissions:

| Permission | Allows |
|---|---|
| `photos.upload` | `POST /admin/photos` |
| `photos.edit` | `PATCH /admin/photos/{id}`, `POST /admin/photos/{id}/rotate`; batches `PATCH /admin/photos`, `POST /admin/photos/rotate` |
| `photos.delete` | `GET /admin/photos` (trash view), `DELETE /admin/photos/{id}`, `POST /admin/photos/{id}/restore`, batches `POST /admin/photos/trash` and `/restore`, opening trashed photos |
| `photos.purge` | `DELETE /admin/photos/{id}/permanent`, batch `POST /admin/photos/purge` |
| `photos.export` | `GET /admin/photos/export.csv` (`?status=active\|deleted\|all`, `&collection=favorites\|saves`, `&mine=true`, `&album={id}`, `&ids=1,2,3`). Columns start with `id, source_zip, original_file_name, detail_url, favorites, favorited_by, saves, saved_by, albums` |
| `albums.manage` | `POST /admin/albums`, `PATCH` / `DELETE /admin/albums/{id}`, `POST /admin/albums/{id}/photos` and `/photos/remove`; also sees hidden albums |
| `users.manage` | `/admin/users/*`, **admin role only**, cannot be granted |

`GET /auth/me` and the login response return the effective `permissions` array.

## Managing users

Admins manage accounts from **account menu → Manage users** in the web app, or through the API:

| Endpoint | Does |
|---|---|
| `GET /admin/users` | List accounts with role, grants, effective permissions, status, last login and upload count |
| `GET /admin/users/permissions` | Permission catalogue with labels |
| `POST /admin/users` | `{ username, role, grants?, password? }`. Omit `password` to get a `generatedPassword` back once |
| `PATCH /admin/users/{id}` | `{ role?, grants?, disabled? }` |
| `POST /admin/users/{id}/password` | `{ password? }`. Resets it (generated when omitted) and signs the user out everywhere |
| `DELETE /admin/users/{id}` | Deletes the account with its favorites and saves. `409` if it uploaded photos: disable it instead |

Admins cannot demote, disable or delete themselves, and the last active admin can't be removed (`403`).

## Role matrix

| Endpoint | Guest | User | Admin |
|---|:-:|:-:|:-:|
| `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout` | ✅ | ✅ | ✅ |
| `GET /auth/me` | `401` | ✅ | ✅ |
| `GET /photos`, `GET /photos/{id}`, `GET /photos/download.zip?ids=` | ✅ | ✅ (with flags; deleted ones with `photos.delete`) | ✅ (can view deleted) |
| `GET /me/favorites`, `GET /me/saves` | `401` | ✅ | ✅ |
| `PUT` / `DELETE /photos/{id}/favorite` and `/save`, `POST /me/favorites/batch` and `/me/saves/batch` | `401` | ✅ | ✅ |
| `POST /shares`, `GET /me/shares`, `GET /shares/people` | `401` | ✅ | ✅ |
| `PATCH` / `DELETE /shares/{id}` | `401` | own links, else `404` | ✅ (any link) |
| `GET /shares/{token}` and `/photos` | public links ✅, private `401` | public ✅, private only if chosen (else `403`) | ✅ |
| `/admin/photos/*` | `401` | per granted permission, else `403` | ✅ |
| `/admin/users/*` | `401` | `403` | ✅ |

Permissions are enforced on the server for every request, not just hidden in the UI.

## Caching note

List responses for requests **without** `Authorization` are publicly cacheable for 30 seconds
(`Cache-Control: public, max-age=30, stale-while-revalidate=60`, `Vary: Authorization`). Responses to requests with a
token are `private, no-cache`, and `/me/*` and `/admin/*` are `no-store`.
